通用开发 loop
任务产生 → 执行并完成 → 独立判断 → 接受或返工 → 更新整体 → 下一任务
1. 执行层
一次只处理一个明确任务。先产出完整结果；执行过程中可以解决实际问题，但不自发启动 Yes/No 判断，也不边产出边宣告通过。
2. 判断层
任务完成、结果固定后，由外层 loop 单独触发一次“判断”。此时依据任务目标、已有上下文和实际结果列出判断点，再逐点独立给出 Yes/No＋置信度。
判断点可分组：依据是否可靠、结果是否必要、与整体是否自洽、能否实际落地。组和具体点随任务而变，不套固定清单。
3. 回流层
- 关键点全 Yes，且置信度足够：接受结果，更新整体，再产生下一任务。
- 出现 No：判断阶段只指出未通过的点；另开返工任务。返工完成后重新独立判断。
- 置信度不足：先形成补证据任务，不视为通过。
核心约束是：生成与判断不同时进行；判断只在任务完成后触发；一个任务、一次独立判断、一次明确回流。
